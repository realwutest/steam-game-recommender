Steam Game Recommendation System

Introduction

Our group implemented a collaborative filtering recommender system to generate personalized video game recommendations using a public dataset of user behaviors from Steam, the world’s most popular PC gaming hub. After constructing a user-item interaction matrix, we used K-nearest-neighbor style similarity methods with cosine similarity to compare games and users based on collective playtime patterns. Our model aims to achieve two primary objectives: first, to recommend 10 similar games given a specific game title (Item-to-Item), and second, to generate 10 personalized game suggestions for a unique user ID based on their past history while filtering out already-played games (User-to-Item). With Steam’s massive collection spanning from AAA blockbusters to small indie titles, developing robust discovery tools is a highly valuable asset for enhancing player engagement. Our group was interested in this project because it allowed us to work with a large-scale behavioral dataset and create a predictive model with practical, real-world applications.

Data Descriptions

We obtained our behavioral dataset by downloading the public Steam Video Games dataset from Kaggle. The dataset is structurally static, capturing a comprehensive snapshot of digital interactions without requiring real-time API streaming. The dataset consists of exactly 200,000 observations and 4 primary predictors: user_id, game_title, behavior, and value. The dataset contains zero missing values.

The variables we are working with represent two distinct data types.

Categorical Variables user_id (the unique identifier for each user), game_title (the name of the Steam game), and behavior (the type of user interaction, classified as either ‘purchase’ or ‘play’).

Numeric Variable value, which represents the degree to which the behavior was performed (a binary 1.0 for ‘purchase’, or a continuous measure of play-hours for ‘play’).

Notably, the raw CSV file lacks a predefined header row. To prevent any data loss or structural misinterpretation during data ingestion, we will explicitly load the dataset using the header = FALSE option in R to preserve all 200,000 rows. Additionally, we found that the fifth column contains a value of exactly 0 across all observations, which serves as an empty placeholder for specific software engine formats. Since this column carries no substantive statistical information for our collaborative filtering model, we will explicitly drop it during the initial data-cleaning phase, ensuring a clean 4-variable matrix for our K-Nearest Neighbors (KNN) model.

Methodology

Background Information

To construct our recommendation engine, we use memory-based collaborative filtering combined with a K-Nearest Neighbors (KNN) style approach. Collaborative filtering operates on the general idea that users or items with similar past interaction patterns can help predict future preferences. Rather than relying on descriptive item features such as game genres or developers, our approach computes similarities directly from user behavior. In the item-based model, we compare game vectors to find similar games. In the user-based model, we compare user vectors to recommend games that similar users played.

To measure the proximity between different video games in a high-dimensional space, we employ Cosine Similarity as our primary distance metric. Mathematically, the cosine similarity \(S_C\) between two game vectors \(A\) and \(B\) is defined as:

\[S_C(A,B) = \frac{A \cdot B}{\|A\|\|B\|} = \frac{\sum_{i=1}^{n} A_i B_i} {\sqrt{\sum_{i=1}^{n} A_i^2}\sqrt{\sum_{i=1}^{n} B_i^2}}\]

The metric outputs a score bounded between 0 and 1 (since interaction values are non-negative), where 1 indicates identical user interaction patterns and 0 represents complete orthogonality (no shared users). By computing these scores across all pairs, the KNN algorithm can effectively identify the \(K\) closest neighbors (most similar games) for any given target item.

Project Steps

Our methodology follows a structured recommendation system pipeline consisting of four major stages:

  1. Data Loading and Initial Preprocessing:
    We load the Steam video game dataset in R and remove the unnecessary fifth column containing only zeros. We then retain only the relevant variables: user ID, game title, behavior type, and interaction value. Since playtime better reflects user engagement than purchase records, we focus specifically on rows where behavior == "play".

  2. Data Cleaning and Sparsity Reduction:
    To improve the quality of the recommendation system, we filter out inactive users who played only a very small number of games and unpopular games with very few user interactions. This step reduces sparsity in the dataset and improves the stability of collaborative filtering methods.

  3. Exploratory Data Analysis (EDA):
    We analyze the distribution of playtime, user activity, and game popularity to better understand the characteristics of the dataset. The analysis reveals strong right-skewed and long-tail interaction patterns, which are common in recommendation system datasets.

  4. Collaborative Filtering Model Construction:
    After preprocessing, we construct a user-item interaction matrix where rows represent users, columns represent games, and values correspond to playtime hours. Using collaborative filtering techniques based on cosine similarity and nearest-neighbor methods, we generate personalized game recommendations.

    • Model 1 (Item-Based Recommendation):
      Given a specific game title, the model identifies and recommends similar games based on interaction patterns among users.

    • Model 2 (User-Based Recommendation):
      Given a specific user ID, the model recommends games that similar users have played while excluding games already played by the target user.

Item-Based Recommendation Model

The item-based recommendation model compares games to other games using user playtime behavior. Each game is represented as a vector of users, and each value in the vector is the transformed number of hours that user played the game. Games with similar playtime patterns across users are treated as similar items.

The model does not use genre, developer, price, or tags. It only uses player behavior. Cosine similarity is used because it compares the shape of two playtime vectors instead of only comparing total playtime. This is useful for the Steam data because some users have extremely large playtime values.

Before creating the matrix, log1p(hours_played) is used instead of raw playtime. This keeps larger playtimes meaningful while reducing the effect of extreme values.

Build the Item-User Matrix

# Combine repeated user-game rows and dampen very large playtime values
steam_model <- steam_clean %>%
  group_by(user_id, game_title) %>%
  summarize(hours_played = sum(hours_played), .groups = "drop") %>%
  mutate(play_weight = log1p(hours_played))

user_index <- factor(steam_model$user_id)
game_index <- factor(steam_model$game_title)

# Rows are games, columns are users, and values are transformed playtime.
item_user_matrix <- sparseMatrix(
  i = as.integer(game_index),
  j = as.integer(user_index),
  x = steam_model$play_weight,
  dimnames = list(levels(game_index), levels(user_index))
)

Cosine Similarity Function

The function below calculates cosine similarity between a selected game and every other game in the item-user matrix. It then returns the 10 games with the highest similarity scores.

recommend_similar_games <- function(target_game, item_matrix, n = 10) {
  if (!target_game %in% rownames(item_matrix)) {
    stop("This game title is not in the item-user matrix.")
  }

  target_vector <- item_matrix[target_game, , drop = FALSE]

  # Compare the target game vector to all other game vectors.
  dot_products <- as.numeric(item_matrix %*% Matrix::t(target_vector))
  item_norms <- sqrt(Matrix::rowSums(item_matrix^2))
  target_norm <- sqrt(sum(target_vector^2))

  similarity <- dot_products / (item_norms * target_norm)
  similarity[!is.finite(similarity)] <- 0

  tibble(
    game_title = rownames(item_matrix),
    cosine_similarity = similarity
  ) %>%
    filter(game_title != target_game) %>%
    arrange(desc(cosine_similarity)) %>%
    slice_head(n = n)
}

User-Based Recommendation Model

Next is the user-based recommendation model. The main concept for this model is to recommend games based on a chosen user’s past history. To do this, we use the target user’s playtime pattern to find similar users in the Steam dataset. These similar users, or neighbors, spent time on some of the same games as the target user, so their other games can be used as possible recommendations.

Like the item-based recommendation model, this model uses only player behavior. If another user played many of the same games as the target user and had a similar pattern of transformed playtime values, that user receives a higher cosine similarity score. This makes the method consistent with the collaborative filtering approach from the lecture slides.

We first transposed the user-item matrix created previously so that the rows are for users and the columns are for games. This is to keep the similarity function the same as from the previous model in order to output cosine similarity scores of similar users.

# Matrix Transposition (User IDs x Game Titles)
user_item_matrix <- t(item_user_matrix)

Similar Users

We take the same cosine similarity idea from the item-based model, but this time we apply user-based collaborative filtering by comparing a chosen target user with the other user vectors. By default, this returns the top 10 nearest neighbors along with their calculated cosine similarity scores.

# Function for Similar Users
similar_users <- function(target_user, user_matrix, n = 10) {
  if (!target_user %in% rownames(user_matrix)) {
    stop("This user ID is not in the user-item matrix.")
  }

  target_vector <- user_matrix[target_user, , drop = FALSE]

  dot_products <- as.numeric(user_matrix %*% Matrix::t(target_vector))
  user_norms <- sqrt(Matrix::rowSums(user_matrix^2))
  target_norm <- sqrt(sum(target_vector^2))

  similarity <- dot_products / (user_norms * target_norm)
  similarity[!is.finite(similarity)] <- 0
  names(similarity) <- rownames(user_matrix)
  
  users <- tibble(user_id = rownames(user_matrix), cosine_similarity = similarity) %>%
    filter(user_id != target_user) %>%
    arrange(desc(cosine_similarity)) %>%
    slice_head(n = n)
  
  return(users)
}

Game Recommendations from Similar Users

We then create another function to recommend games based on the neighbors’ other game interests. The recommendation score is calculated using a similarity-weighted average of neighbor playtime weights. After applying the similarity function, we also identify the games that the target user has already played. Those games are removed from the recommendation list because recommending something the user already played would not be useful. By default, this returns the top 10 recommended games.

# Function for Game Recommendations by Neighbors
recommend_games_by_user <- function(target_user, user_matrix, k, n = 10) {
  recommended_users <- similar_users(target_user, user_matrix, n = k)
  played_games <- names(which(user_matrix[target_user, ] > 0))
  
  score <- rep(0, ncol(user_matrix))
  sim_total <- rep(0, ncol(user_matrix))
  names(score) <- colnames(user_matrix)
  names(sim_total) <- colnames(user_matrix)

  for (i in seq_len(nrow(recommended_users))) {
    neighbor <- recommended_users$user_id[i]
    similarity <- recommended_users$cosine_similarity[i]
    neighbor_vector <- as.numeric(user_matrix[neighbor, ])
    score <- score + similarity * neighbor_vector
    sim_total <- sim_total + similarity * as.numeric(neighbor_vector > 0)
  }

  score <- ifelse(sim_total > 0, score / sim_total, 0)
  score[played_games] <- 0

  tibble(game_title = names(score), rec_score = score) %>%
    arrange(desc(rec_score)) %>%
    slice_head(n = n)
}

Conclusion

This project shows that collaborative filtering can be used to build a Steam game recommendation system from user behavior alone. After cleaning the original 200,000-row dataset, the analysis focused on play behavior because playtime gives a stronger signal of interest than purchase records alone. The EDA showed a right-skewed dataset where a small number of games and users account for a large share of activity, so inactive users and unpopular games were filtered before modeling.

The final recommender system includes two models. The item-based model compares games based on shared player behavior and returns similar games for a selected title. The user-based model finds similar users, scores games from those neighbors, and removes games the target user already played.

The main limitation is that the system relies only on past interactions. This can favor popular games and makes brand-new games difficult to recommend. A stronger future version could combine collaborative filtering with Steam metadata such as genre, tags, reviews, or release year. Even with these limits, the models turn the Steam dataset into practical item-to-item and user-to-item recommendations.
